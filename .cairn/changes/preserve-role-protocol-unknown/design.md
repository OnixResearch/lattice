## Decisions

Adapter selection is deterministic and preflighted after current authorization and before DispatchedUnknown. The shell retains selected references throughout ordered fanout. Before each first possible adapter effect, DispatchedUnknown remains durably persisted. A first RejectedBeforeStart is a positive adapter guarantee of no receiver work and uses a distinct rejected-before-start outcome. A later rejection cannot close the attempt.

The HTTP profile admits no application rejection receipt from the response. 2xx is Started; all other statuses are UnknownAfterStart. Unbound ObservedFailure is also unknown. Exact observations continue through Runtime::observe and the existing pure canonical envelope admission. An embedding authenticates its receiver evidence before calling this trusted API; an identity string is not a signature.

All accepted observations can commit atomically. All rejected exact observations can fail. Mixed acceptance/rejection cannot roll back an accepted recipient and therefore stays blocked until acknowledged recovery, rather than unlocking blind resend.

## Independent Fixture Contract

A deterministic local HttpClient records actual canonical operations and effect counts in a JSON file independent of redb. Each record also binds a stable logical-operation key to the session, protocol cursor, source, destination and payload context, excluding attempt/message/authority-request identities that change on retry. The independent checker aggregates deliveries and effects by this key so a fresh canonical retry cannot hide duplicate work in a second record. Its response status is independently selected from 202, 500, 502 or lost ACK. Not-applied is an explicit receiver rejection, applied-once is completed, and in-progress has no observation until a later generation completes. No-start adapter rejection persists the exact envelope with zero deliveries/effects, including a later fanout recipient; reconciliation authenticates this current record through the same observer as acceptance. Current exact record comparison precedes runtime observation; it rejects stale, substituted and unavailable records. The profile deliberately has no idempotent suppression so accidental retries are detected.

The parent test can spawn the integration-test binary as a child, dispatch, let it exit, and reopen the database and ledger in a fresh process. This exercises process restart, not arbitrary power-loss durability. Agent history representations are independent labeled inputs and never write authoritative records. A deterministic reader consumes every transcript line to derive the supplied completion/retry intent, including additive corrections and false rewritten handoffs. Safe handoff reconstruction replays persisted events and derives external-completion claims from admitted per-message observations plus current receiver records; supplied intent cannot change authority, durable disposition or idempotency identities, and reconstruction starts no work. Broken controls use the same reader but trust its false claims: done on an uncompleted operation fails the completion oracle, and failed after actual completion starts a second persisted effect. The retry control covers both the same message and a real fresh `retry_unknown` attempt, deliberately inventing risk acknowledgment from prose. An independent checker checks actual logical-operation/message identities, counts, completion and compensation; false completion and duplicate/compensation controls must fail it.
