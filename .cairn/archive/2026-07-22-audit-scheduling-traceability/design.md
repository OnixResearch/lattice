# Design: audit scheduling traceability

## Success contract

Exactly all seven scheduling rows MUST receive reviewed classifications while the 324-item missing set remains unchanged. Exact rows require direct maintained evidence for every accepted clause. Partial rows MUST name the unproved clause and MUST NOT be treated as near-complete correctness.

## Portfolio registry

| Family | Mechanism | Expected discriminator |
|---|---|---|
| clause-match | Match GIVEN/WHEN/THEN clauses to direct assertions | Reject test names and parent markers. |
| state-and-effects | Trace admission, persistence, execution, and socket effects | Distinguish pure planning from observed side effects. |
| provenance-exclusion | Exclude implementation-only shape, archives, and generated inventory | Require current repository-owned test identity. |

These are correlated serial repository passes. Advisory local-model review may veto overclassification but deterministic tests and repository validators remain authoritative.

## Classification boundary

Disabled admission, valid and invalid webhook handling, and the cookbook operator flow have exact composite assertions. Trigger terminal history is partial because persisted `Started` evidence does not establish terminal status plus every required field. Scheduler compatibility is partial because no full old/new due-plan comparison exists. Listener startup is partial because implementation binds a socket but no maintained live process/socket test observes startup and request acceptance.

## Non-claims

Inventory rows create no Tracey evidence. Exact composite evidence is bounded to the accepted clauses and does not prove arbitrary transport, remote effects, release readiness, or production readiness.
