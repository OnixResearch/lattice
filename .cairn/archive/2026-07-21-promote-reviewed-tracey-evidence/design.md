## Context

The maintained Cairn coverage receipt reports 702 accepted requirements, 335 referenced requirements, 367 missing identifiers, zero dangling identifiers, and `valid: false`. The debt inventory records six missing scenarios as exact maintained-evidence candidates. Promotion must link only those exact scenario assertions; it must not convert file presence, parent markers, lexical similarity, or inventory classification into evidence.

## Goals

- Link exactly the six reviewed safe inspection/recovery scenario identifiers.
- Place markers beside precise supporting tests rather than at file scope.
- Strengthen tests for missing-run non-synthesis, not-recorded semantics, exact owner binding, invalid replay exits, and bounded recovery claims.
- Prove the current missing set equals the baseline set minus the six allowlisted identifiers.
- Preserve zero dangling markers and unsuccessful Tracey coverage.
- Regenerate a valid BLAKE3-bound inventory for all 361 remaining gaps.

## Non-Goals

- Promoting any unassessed inventory row.
- Claiming test markers prove whole-system correctness, complete traceability, release readiness, or production readiness.
- Changing run inspection, recovery, orchestration, or persistence behavior.
- Treating archived lifecycle evidence as maintained Tracey evidence.
- Making Tracey coverage pass.

## Portfolio Search Contract

**Exact goal:** promote six and only six reviewed scenario identifiers into maintained Tracey evidence.

**Completion evidence:** the baseline missing array has 367 unique IDs; the final array has 361; set subtraction equals the six-ID allowlist; the final set adds no ID; dangling remains empty; final coverage remains invalid; each marker is attached to an exact supporting test; the generated inventory validates against the final receipt.

**False completion:** file-scope markers, parent-only linkage, approximate scenario mapping, an unrelated missing-ID change, a dangling marker, a green coverage claim, stale inventory provenance, or accepting test count/process exit without exact set comparison.

**Budgets:** accepted workflow-execution and repository-validation specs; current inspection/recovery tests; maintained inventory policy/tool/report; one local advisory review; no network retrieval; one implementation round and one adversarial validation round.

**Allowed outcomes:** validated exact promotion, a bounded blocker naming a scenario without exact assertions, or a user decision if the accepted requirement requires behavior beyond maintained authority.

## Adversarial Audit

A local secondary review accepted the safe-output, owner-binding, replay, and recovery non-claim candidates and challenged the missing-run and not-recorded candidates as insufficiently explicit. The implementation therefore strengthens those two surfaces. It also adds stricter owner instance/run mismatch and CLI invalid-replay assertions rather than relying on the advisory review's acceptance.

## Decisions

### Decision: evidence markers attach to complete tests

A marker is placed immediately above each supporting `#[test]`. A scenario may have more than one marker occurrence when positive and negative assertions jointly establish the accepted contract. No promoted marker is placed on helpers, modules, generated files, inventory policy, or lifecycle prose.

### Decision: promotion is a deterministic set transformation

A pure test core compares baseline and current in-memory coverage DTOs. It rejects duplicate IDs, non-empty dangling arrays, valid coverage, any added ID, any unexpected removed ID, or a final count inconsistent with the six-ID allowlist. Positive and negative tests use checked-in receipts generated by the maintained Cairn profile.

### Decision: reviewed debt disappears from the review registry

After promotion, the six IDs are no longer missing and therefore cannot remain legal reviewed decisions. The Nickel policy pins the new 361-ID missing-set BLAKE3, uses an empty reviewed list, and preserves explicit uncertainty for every remaining row.

### Decision: test hardening changes no product authority

The change adds assertions and fixtures only. Lattice's inspection and recovery behavior, data model, authority boundaries, and durable formats remain unchanged.

## Risks and Mitigations

- **Risk:** a marker attaches to only part of a scenario. **Mitigation:** strengthen CLI and pure-core assertions, and allow multiple precise test attachments where positive and negative cases jointly establish the contract.
- **Risk:** unrelated markers change concurrently. **Mitigation:** compare exact before/after sets and fail on additions or unexpected removals.
- **Risk:** promoted IDs remain in inventory policy. **Mitigation:** inventory generation rejects reviewed IDs not present in the current missing set.
- **Risk:** generated receipts become accidental evidence authority. **Mitigation:** Tracey scans maintained source roots; fixtures validate set transitions but do not satisfy workflow-execution scenarios.
