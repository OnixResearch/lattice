# Design: audit workflow-example traceability

## Success contract

The generated inventory MUST classify exactly the two workflow-example rows, retain all 327 missing IDs, report zero dangling markers, remain `valid: false` for coverage, and add no selected marker.

False completion includes parent image-example markers, implementation support, unrelated image rejection tests, archived material, generated inventory, and a plausible but absent invalid fixture.

## Portfolio review

Three correlated repository lenses are bounded to accepted clause matching, maintained fixture/test discovery, and adversarial marker/provenance exclusion. Retrieval is limited to the accepted spec, current inventory, `examples/workflows`, and repository-owned tests; no web or advisory model is authoritative.

The selfie scenario is exact because its maintained Nickel example and direct integration test observe import, three image inputs, fake Clankers dispatch, all-node completion, and generated image output. The invalid scenario is `no_exact_evidence_identified`: maintained tests reject unsupported images generally, but no intentionally invalid workflow-example fixture is present and no test observes no partial workflow state for that fixture.

## Validation

A pure review validator checks the exact two-row expectation table, safe evidence paths and hashes, absence of selected markers, unchanged coverage, and deterministic negative mutations.

## Non-claims

`no_exact_evidence_identified` is bounded to reviewed maintained roots and is not proof of global absence. Audit rows create no Tracey evidence and prove neither requirement satisfaction nor release readiness.
